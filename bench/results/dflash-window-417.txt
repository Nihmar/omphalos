# #417 follow-up: the DFlash2 drafter's attention window as a knob

Engine main 0571d06 + `perf/417-dflash-window`, RX 9060 XT 16 GB. `omph-run
--last-logits --gemv --generate 384 --dflash <drafter.omph>`,
`OMPH_DFLASH_KEEP=0`, the new `OMPH_DFLASH_WINDOW=N` overriding the model's
`dflash.attention.sliding_window` (2048) for the *attention* only (the ring's
allocation and its tags stay the model's). Prose / code2k / repetitive / edit
median of 5, wiki16k single runs (a 16k prefill each). Tokens identical across
windows on every text (`cmp`).

| text (prompt tokens) | 1024 | 1536 | 1792 | 2048 (the model's) |
|---|---:|---:|---:|---:|
| prose (283, ring not full) | 5.300 | | 5.290 | **5.290** |
| code2k (2000) | **5.720** | 5.900 | 6.060 | 6.080 |
| repetitive (2477, ring full) | **5.520** | | 5.710 | 5.870 |
| edit, file + task (2311, ring full) | 8.040 | 7.760 | **4.810** | 5.140 |
| wiki16k (16384, ring full) | 6.640 | | **6.520** | 6.540 |

(1792: medians of 5 on code2k and edit, two runs on repetitive, three on
wiki16k; every cell's tokens equal plain greedy.)

ms/token; the prose row is the control (the ring never fills, so no effect), and
it shows the run-to-run spread is 0.01 ms.

## Reading

- The window is a **workload-dependent trade**: a shorter one makes the drafter's
  attention cheaper (its cost scales with the ring occupancy: 1.34 ms/step at a
  full ring against 0.29 at 283 keys, `dflash-attn-245.txt`/rocprofv3) and can
  *raise* the acceptance on local text (code2k +6.3 %, repetitive +6.3 %) - the
  model's far context is not always useful.
- It is not monotone and not safe: on the file-edit prompt 1792 beats the trained
  2048 by 6.9 % while 1536 loses 51 %, and on the 16k wiki text 1024 loses 1.5 %.
  The task's *relevant* context sits at a specific distance; a window that
  excludes it destroys the drafts, one that includes more of it than needed
  merely dilutes them.
- **1792 is >= the trained 2048 on all five texts** (edit +6.9 %, repetitive
  +2.7 %, code2k +0.3 %, wiki16k +0.3 %, prose unchanged), so the engine's
  default is 1792 (`OMPH_DFLASH_WINDOW=0` restores the model's own value).
  Shorter than that is a workload-specific trade: 1024 wins more on local text
  (code2k +5.9 % over 1792) and loses badly where the context is far back (the
  file-edit prompt -40 %), with the numbers above as the warning.

## The masks interaction, and the new default pair

With the window at 1792 the block length is re-measured (384 tokens, `KEEP=0`):

| text | 11 masks | 15 masks |
|---|---:|---:|
| prose | 5.30 | **5.11** |
| code2k | 6.05 | 6.06 (tie) |
| repetitive | 5.71 | 5.70 (tie) |
| edit | 4.81 | **4.76** |

15 masks dominated 11 at the 2048 window on prose (+3.7 %) and lost on code
(-5 %); at 1792 it wins on prose and edit and ties on code and repetitive, so the
engine's default is now **15 masks with the 1792 window**. Against the previous
default pair (2048 + 11), medians of 5: prose 5.290 -> **5.120** (+3.3 %), edit
5.140 -> **4.76** (+7.4 %, three runs), repetitive 5.870 -> **5.70** (+2.9 %),
code2k 6.080 -> 6.070 (a tie). Tokens equal to plain greedy in every
configuration.

(The 15-mask figure at 1792 is a single run on code2k/repetitive and three on
edit; the 5-run medians are for the shipped pair on prose and code2k.)

The measurement closes #417's "smaller LDS footprint" idea from the other side:
the ring's *reads* can be cut, and the cost is the drafts' quality, not the
kernel.
