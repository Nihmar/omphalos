#
# Read:
#
# 1. The penalties are the simple fix the loops were missing. The 11:44:19
#    prompt without them repeats paragraph after paragraph: 23 pairs at 0.85
#    or more, 13 of them verbatim, and loop-police's fingerprint would truncate
#    at 59 % of the stream. All three settings take it to zero pairs in the
#    same conditions -- and to 0.48-0.72 worst pair, i.e. the reasoning is not
#    re-deriving anymore.
# 2. The window is what matters. llama.cpp's default (64 tokens, pen-short)
#    leaves 0.943 on the 98k prompt -- it cannot reach a repeated block that is
#    hundreds of tokens long -- while the same penalty with 1024 leaves 0.721
#    and no pair at all. `--repeat-penalty 1.1 --repeat-last-n 1024` is the
#    setting to start from.
# 3. Presence/frequency (OpenAI's pair) help too, less: no verbatim repeat and
#    no firing, but 3 pairs at 0.991 on the 98k prompt.
# 4. The penalized runs also *end*: 889-3346 tokens instead of always hitting
#    the 4096 cap. The model stops deliberating because its own recent text
#    cannot be reused, which is the failure mode the user was fighting.
#
# Caveats: two prompts, one seed each; the penalties cost the legitimate reuse
# of identifiers and paths in a coding session, which is why the README says to
# fall back to 1.05 rather than up when the answers get worse. Nothing here
# says the penalties fix the *greedy* re-derivation (#287's greedy rows repeat
# no tokens, only the plan) -- they are for the sampled regime, which is the
# one that was looping.
#
