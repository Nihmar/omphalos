## The bug found by the per-expert comparison

The down projections of the experts have no fused GEMV in this file (Q3_K,
identity layout), so `matmul` took the staged path, which staged the weights by
tensor name - every expert read expert 0's rows. `Mat::sliced` +
`Runner::stage_slice` stage from the slice's own pointer now. Before the fix the
end-to-end KL was 0.962 nats (top-1 still 100 %).

The residual 0.0045 nats is the engine's existing approximation class (f16
activations, the q8-quantized inputs of the fused GEMMs, f16 scale application
in the staged paths), not a MoE-specific term: the per-layer agreement is
0.5-1.5 % up to layer 29. The same comparison against the first model, with the
same probe, is the control that says whether it can be tightened.
