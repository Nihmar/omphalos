# Read:
#
# 1. The loops are the context, not a knob. 14 of the 16 streams end in a
#    near-duplicate paragraph pair (>= 0.85), 7 of them with at least one
#    verbatim repeat, and the model is doing what it did that day: re-deriving
#    the same CommonMark rule (in the pre-compaction cuts), or the same
#    `_quoteDepth` / list-marker analysis (in the post-compaction ones). A
#    fresh single-turn prompt never repeated a paragraph
#    (bench/results/loop-rate-287.txt), so what matters is the agent's own
#    reasoning of every earlier turn plus the tool results it was reacting to.
#
# 2. With four prompts no configuration dominates. #295 replayed only the
#    09:17:56 cut and it made K4-everywhere look like the outlier: that stream
#    is still the worst of the sixteen (21 pairs, 17 verbatim, the detector
#    fires at 91 %), but the same configuration is clean on the other three
#    cuts, while the sampled configuration repeats worst on the 11:44:19 cut
#    (14 pairs, 6 verbatim). One stream is not a ranking: the K4 hypothesis of
#    #175 stays plausible for the longest prompts and is not established here.
# 3. The one directional signal: none of the four greedy runs over the default
#    mixed KV produced a verbatim repeat (0 of 130 paragraphs), while K8, K4
#    everywhere and the sampler each did (3, 17 and 7), and the two sampled
#    runs that did also wrote the longest reasoning (3047 and 2548 tokens).
#    Greedy is not "safe" -- its worst pair is 0.94 -- but it is the only
#    configuration that never fell into a verbatim loop here.
#
# 4. loop-police's own settings (bench/results/loop-rate-287-sweep.csv, the
#    same 16 streams): its default semantic detector would have truncated 3 of
#    the 16, at 47 %, 79 % and 91 % of the stream -- i.e. late, after the
#    repetition is already there. Raising the threshold from 3 to 5 silences
#    all three, including the stream with 17 verbatim paragraphs: the detector
#    is not over-firing, it is under-firing. A paragraph floor of 160 chars or
#    a 120-char fingerprint removes one or two of the three. What it cannot
#    see is the common case here -- the same plan re-derived in different
#    words, two paragraphs at 0.9+ that do not share their first 60 characters
#    -- so if the goal is to truncate these streams, the rule to add is a pair
#    similarity one (two paragraphs >= 0.9), not a tighter threshold.
#
